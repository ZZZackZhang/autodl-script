# AutoDL 頁面判讀

以下於 2026-10-30 至 2026-10-31 從使用者已登入的 Chrome 頁面實際觀察。只供辨認欄位；型號、庫存、價格、地區及頁面結構會變，以執行時的新頁面為準。此技能製作期間未下單。

## 算力市場

- 入口：<https://www.autodl.com/market/list>，頁面標題為 AutoDL 算力雲。優先沿用使用者開啟的 AutoDL 分頁或可見導航。
- 可見篩選：`计费方式`（`按量计费`、`包日`、`包周`、`包月`）、`选择地区`、`GPU型号`、`GPU数量`。
- 地區用單選，不能假設選中一區會同時搜尋所有區。GPU 型號是勾選項，旁邊可能顯示 `(空閒/總數)`；這是彙總資訊。
- 主機卡片包含：地區、主機名稱／ID、`可租用至`、GPU 型號／顯存、`空闲/总量`、`每GPU分配` 的 CPU／RAM、`系统盘`、`数据盘`、`可扩容`、GPU 驅動／CUDA 及價格。
- 有庫存的候選可見 `1卡可租` 等按鈕；無庫存時可見停用的 `已租完`。必須對應同一張主機卡片核對所有條件。
- 模型名稱可能非常相近，例如 `RTX 4090` 與 `RTX 4090D`、`RTX PRO 6000` 與 `RTX 6000D`；`vGPU` 也不能視為相同型號的實體卡。
- 原生無障礙樹可能顯示 `showing 0-100 of ... items`，不能把截斷的樹當成完整庫存。依目前 UI 捲動、分頁或載入更多。
- 從可租按鈕會進入建立頁。其路徑包含地區及主機 ID，必須沿用實際導航結果，不能硬編其他主機的路徑。

## 建立實例

- 可見 `选择主机` 表格，欄位有 `主机ID`、`算力型号/显存`、`空闲GPU`、`每GPU分配`、`CPU型号`、`硬盘`、`驱动/CUDA`、`价格(单卡)`。
- 下方有 `GPU数量`；沒有足夠空閒張數的選項會停用。進入建立頁並不代表已保留庫存。
- `数据盘` 常見 `免费50GB` 與 `需要扩容`。展開後的容量輸入欄是**額外付費容量**：曾驗證填入 `100` 後摘要為 `免费50GB SSD，付费100GB`，總共 150GB。市場的 `可扩容 ... GB` 是可加容量提示，**不是目前實例已配置的總容量**；仍須以當下的輸入範圍、摘要及費用核對。
- 擴容提示曾顯示按量付費盤每日每 GB 收費、每日 24 點扣款，而且**無論實例是否關機都收費**。這類費用即使未反映在頁尾數字也必須納入支出計算；執行時讀取當下單價，不硬編本次觀察的價格。
- `实例规格` 摘要包含 GPU 張數、CPU、RAM、系統盤與數據盤。原生 AX 勾選值曾先更新而擴容欄較晚出現，故不能只憑無障礙勾選值判定配置成功。沒有產生預期更新時重讀頁面；`setValue` 未更新容量時，可點選欄位、全選、輸入數字並失焦，再查核摘要。必要時依最新截圖改用原生座標點擊；不要重用舊索引或猜座標。
- 鏡像有 `基础镜像`、`社区镜像`、`我的镜像`。基礎鏡像選擇器提示為 `请选择框架名称/框架版本/Python版本/CUDA版本`。沒有選定有效鏡像就可能無法建立。
- 本次在西北B區 vGPU-48GB 主機逐層檢視全部基礎鏡像分支，觀察到 PyTorch、TensorFlow、Miniconda、tritonserver、JAX、PaddlePaddle、TensorRT、Gromacs，共 36 組完整版本組合；快照保存在 `assets/webui/catalog.js`。這是該主機可見選項，不推定其他架構也相同。社區搜尋可切換 `镜像名称` 或 `应用名称/ID`；熱門列表及私人鏡像依帳戶與時間動態變化，執行時搜尋並逐項核對。
- 頁面有優惠券選單，但本次未核實可用券及其條件。快照估價不扣除優惠券、不承諾會員折扣；執行時只有網站確實套用且無新增付費或條款的既有優惠，才可按實際成交價比較。
- 頁尾可見 `日常费用`（每日）、`配置费用`（例如每小時）、`费用明细`、`账户余额`。比較價格時包含必要的每日儲存費；區分未取得的折扣／刪除線原價與真正可用的成交價。
- 提交按鈕常為 `创建并开机`。按鈕停用的原因可能包含餘額不足、未完成配置或缺貨，不能一律當作缺貨。
- `余额不足去充值` 不是下單成功，也不是繼續刷新可解決的問題。本技能不自動充值。

## 結果查核

頁首可見 `控制台`。執行時由可見導航尋找實例／訂單清單，記錄既有 ID 及成功後的新 ID。本次沒有實際提交訂單，因此不固定成功訊息、成功頁 URL 或控制台欄位；必須以當下真實頁面確認。

## Chrome 橋接與視窗一致性

- Chrome 擴充功能可能已開啟而工具仍回報 `native pipe closed before response`。這屬於工具橋接問題，並不表示 AutoDL 登出；原生 `cua.getApp("Google Chrome")` 曾能正常讀取同一已登入頁面。
- 原生 Chrome 有多個視窗時，曾出現 **AX 樹、截圖及實際接收鍵盤／滑鼠輸入的視窗不一致**。AX 顯示某地區或計費方式，不代表截圖與下一次點擊就屬於那一頁；不能把不同視窗的硬體、價格、已選值或按鈕組合成一份配置。
- 有疑義時，先透過目前 CUA 提供的 Chrome 原生選單操作，在 `Window`／視窗選單選定目標視窗。選定後重新取得該視窗的 AX 與截圖，核對地址列 URL、頁面標題、目前分頁、計費方式及選中地區；建立頁還須核對主機 ID、張數、鏡像、磁碟與費用摘要。地址列和頁面內容須相互一致，不能只信任其中一項。
- 切換視窗／分頁、刷新或操作篩選後，讀取新 AX，確認更新的是所選真實頁面；若仍在載入，待預期頁面出現再繼續。重新取得的索引只用於對應頁面；用座標操作時依該頁最新截圖定位。不要用反覆點擊、輸入或混用舊索引來猜測修正結果。
- 最終提交前必須確認觀察與輸入均屬於同一頁面。若選定視窗後仍無法核實，保存狀態並停止，說明工具觀察與輸入不同步；不可繼續下單。若先前已提交，先依主技能進入結果查核，無法釐清則保存 `結果不明`，不能當作未下單重送。
